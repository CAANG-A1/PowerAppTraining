Build sequence

Each stage now includes a checkpoint and a short teaching note so learners know what success looks like while you build.

Step 1

Create the SharePoint list

  1. Navigate to the Teams or SharePoint site.
  2. Select New > List.
  3. Create a blank list named Power App Actions.
  4. Add workflow-related columns.
  5. Create a sample test record.
Checkpoint

You should now see a list with five columns and at least one test record.

Say this live

“The list is the filing cabinet. Power Apps is the front desk people use instead of opening the drawers themselves.”

Step 2

Generate an app

  1. Open the SharePoint list.
  2. Select Integrate > Power Apps > Create an app.
  3. Allow Power Apps to generate the app.
  4. Preview the generated app.
  5. Create and edit a sample record.
Checkpoint

You should see a working app connected to the list, with records you can browse and edit.

Say this live

“This is the fastest path to something functional, but not always the best path to something polished.”

Step 3

Build a blank canvas app

  1. Open Power Apps.
  2. Select Create.
  3. Select Blank Canvas App.
  4. Choose Tablet layout.
  5. Connect the app to the SharePoint list.
  6. Build the layout with containers, galleries, and forms.
Checkpoint

You should see a header area, a gallery showing records, and a form tied to the selected item.

Say this live

“Now we are not accepting the default layout. We are deciding what users should see first and what actions matter most.”

Helpful analogies

These short comparisons make abstract concepts easier to explain while you are building live.

SharePoint + Power Apps

Back office and front desk

SharePoint is the back office where the records are stored. Power Apps is the front desk where people view, enter, and update information.

Gallery + form

File list and open file

The gallery is like a list of file names in a folder. The form is the file you open to read or edit after you click one item from the list.

Auto-generated app

Starter apartment

An auto-generated app is move-in ready fast, but you did not design the floor plan. It works, but customization is limited.

Blank canvas app

Custom floor plan

A blank canvas app takes more setup, but you decide where the rooms go, what users see first, and how the experience should flow.

Why blank canvas matters

  • Create custom layouts.
  • Add multiple screens.
  • Control where forms and galleries appear.
  • Create dashboard-style home screens.
  • Add custom navigation and actions.
  • Create a cleaner user experience.
Example to explain

“In an auto-generated app, every field tends to follow the default structure. In a blank canvas app, we can put important fields first, move optional details lower, and guide the user more intentionally.”

Galleries and forms

  • A gallery displays multiple records from SharePoint.
  • Each row in the gallery represents one SharePoint item.
  • Selecting a gallery item changes the form record.
  • A form allows users to create or edit records.
Controls are the building blocks. Power Fx defines behavior. ThisItem refers to the current gallery record. Variables store reusable information. Containers organize layouts and dashboards.

What not to do

Calling out common beginner mistakes during the live build can prevent confusion before it starts.

Avoid this

Skipping the test record

  • Without sample data, the gallery is harder to explain live.
  • It is easier for learners to understand the app when a real row already exists.
Avoid this

Overbuilding the first list

  • Do not start with too many columns.
  • Keeping the list simple helps learners focus on the pattern instead of the clutter.
Avoid this

Customizing the generated app too much

  • Use the auto-generated app to prove the concept quickly.
  • Use the blank canvas app to teach intentional design and layout.
Avoid this

Publishing before previewing

  • Always test in preview mode first.
  • Showing a quick test live reinforces good habits for beginners.
